# Trail Gauge

Trail Gauge helps hikers discover mapped trails across the United States and compare the fit of verified hikes for their group. The static site uses Leaflet maps and stores profiles, groups, and reviews in the browser.

## Foreground GPS prototype

**Track** asks for explicit consent before requesting precise location. Start, Pause, Resume, and Finish save to a separate versioned browser key (`trail-gauge-recordings-v1`); **My hikes** shows completed details and explicit single-record deletion. Existing legacy planning data is retained when migrated. No account, uploads, sharing, or prediction learning is added. Coordinates remain private to this browser, not encrypted against device users; clearing site data/private browsing may lose them. Use only one app tab.

Keep the page visible and screen unlocked. Hiding or leaving pauses tracking; reload recovers a paused draft and requires Resume. A device/browser crash can lose the latest unsaved fix. Limits: four wall-clock hours from Start, 7,200 accepted points per hike, 20 completed hikes, up to 200 quality/interrupt events. Full storage never silently removes older hikes. Storage failure pauses collection and keeps the in-memory draft for retrying Finish. Unsupported/corrupt recording storage is not overwritten.

Fixes must report accuracy within 100 m, be recent and ordered, and avoid implausible jumps. Pauses, rejected fixes, and gaps over 30 seconds break distance segments; recorded distance is approximate and can drift or undercount. No moving-time, background reliability, route safety, or navigation claim. Browser test adapters mark simulated recordings visibly; simulated checks are not real GPS or iPhone evidence.

Location needs a supported browser and a secure context (HTTPS or localhost on the same computer). An iPhone cannot access this Mac's localhost through its own localhost. No secure phone access route or real-device confirmation is established by this prototype. To run an isolated Mac preview without using the existing preview port: `python3 -m http.server 8812 --bind 127.0.0.1 --directory dist`.

Automated checks: `node --test tests/*.test.mjs`. Disposable installed-Chrome flows: `TRAIL_GAUGE_EVIDENCE=<existing isolated evidence directory> node scripts/browser-gps.mjs`; existing catalog/weather/gallery/packing checks: `TRAIL_GAUGE_EVIDENCE=<existing isolated evidence directory> node scripts/browser-check.mjs`. Both browser scripts use disposable profiles and random loopback-only server/debug ports; no installation is needed.

## Existing preview

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

Open [Trail Gauge](http://127.0.0.1:8765/). No build, package installation, or API keys are required. The preview needs internet access for Leaflet, OpenStreetMap, NWS forecasts, and park alerts. Existing browser data belongs to its original origin, so use the same host and port when checking a previous local installation. The production hosting manifest still points to `dist/`.

1. Start in **Explore**. Search verified hikes by trail or park and filter by park, distance, or group fit. Save favorites, mark trails **Would skip**, and restore them from that list.
2. Set up a profile with a nickname, fitness, and experience. Choose hikers in **My Group**. Add account-free guests under **Profiles & local guests**.
3. Add verified hikes to **Compare**. Set a time budget and optionally a hike date and start in each trail’s local time.
4. Open a verified hike for its map, weather limitations, and park conditions. Use **Plan & pack** to save trip settings, review food and water estimates, and edit a group checklist. Log the completed hike to see the review in **Hike history**.

## Phase 2 planning

- **Discovery.** Explore’s park, distance, and fit filters use the eight verified itineraries. The nationwide search and map include mapped USGS segments. **Use my location** asks the browser for permission and looks for nearby verified hikes and USGS segments within about 40 miles. Coordinates are rounded to two decimals for the USGS search and are kept only while the Explore page is open. If permission is denied, use the park filter or the nationwide state selector.
- **Private hiker details.** Comfort ranges, firm limits, terrain preferences, recent hikes, food restrictions, and water details are optional. The app stores these under each hiker’s planning profile in browser storage. Older basic profiles and guests continue to work. The app has no community endpoint, and trail requests contain no profile, diet, water, or hike-review data.
- **Group time and fit.** The moving baseline uses the slower estimated pace, one minute per 100 ft of ascent, and adjustments for known surface and grade, pack load, and weather. It uses uphill and downhill grade when separately reported. The current catalog generally provides a combined grade or no grade. Breaks and overnight stops are added to elapsed time separately. When a profile or log has recent comparable moving time, the app matches up to three outings by distance, climb per mile, pack load when known, and date. It uses the slower plausible result and names the outings. Usual pace and a rough baseline are fallbacks. History can exclude any eligible outing from future estimates. There is no held-out validation set for this preview. Estimates are shown as planning ranges and flagged when the data is sparse. Firm limits can rule out a route. Unverified terrain features can require a check before recommending a hike. Altitude is shown separately. [Travel-time research](https://doi.org/10.1016/j.compenvurbsys.2022.101866) · [NPS group guidance](https://www.nps.gov/articles/hiking-safety.htm) · [CDC altitude guidance](https://www.cdc.gov/yellow-book/hcp/environmental-hazards-risks/high-altitude-travel-and-altitude-illness.html)
- **Packing.** Checklists and trip settings are saved per verified route and group. Suggestions account for moving time, breaks, forecast when available, and optional overnight stops. Snack estimates use logged or typical portions when available. Meal windows, camp meals, and reserve food are separate. Specific foods are excluded if the hiker has an exclusion and has not checked the product’s ingredients. Label data can give snack servings and approximate carbohydrates. The sports fueling reference is optional and does not set portions. Water estimates are editable per person and summed for the group. They distinguish estimated use, starting carry, reserve, and confirmed refill legs. Generic water ranges are packing heuristics. Comparable water logs can refine a range, which widens when conditions or effort differ. A recorded sweat rate is shown as context. The app flags unverified refills and carry capacity shortfalls. Reminders appear only while the app tab is open. [NPS trip planning](https://www.nps.gov/articles/upload/NPS-Trip-Planning-Guide-Package-1.pdf) · [Sports nutrition position statement](https://www.andeal.org/files/files/Collaborations/Position_Athletic-Performance_2016March.pdf) · [Fluid replacement position statement](https://pmc.ncbi.nlm.nih.gov/articles/PMC5634236/)
- **Completed hikes.** Subjective effort, hardest factor, temperature, and sun observations start unanswered; saved answers remain editable. A review can record separate moving and elapsed times, weather, effort, notes, crossings, reception with a date and carrier, and actual food and water use. If the group saved a packing estimate on or before the recorded date, history compares the hiker’s reported use with the saved estimate and shows reported shortfalls. These comparisons describe packing experience. Reviews and reception observations stay in this browser.

## Nationwide trail discovery

The **Browse U.S. trails** screen queries the [USGS National Digital Trails layer](https://carto.nationalmap.gov/arcgis/rest/services/transportation/MapServer/37/query). It supports nationwide name search and browsing within any of the 50 states, Washington, D.C., or Puerto Rico. The layer aggregates public-domain federal, state, and some local data. Coverage varies by area and land manager. Some trails are absent. [USGS coverage and update cadence](https://www.usgs.gov/national-digital-trails/qas-about-usgs-trail-data)

- Results include land trails where hiking is listed or unspecified. The app labels unspecified hiking use and offers unnamed segments when browsing by state. A name can apply to several separately mapped segments. Trail lengths shown in these results are segment lengths. Access and current conditions should be checked with the source land manager.
- The browser sends search terms or the selected area boundary to USGS and loads 24 records at a time. Selecting a result fetches its geometry. Direct links use the USGS permanent identifier where available. If USGS supplies only an object ID, the fallback link may change when the source refreshes. Personal planning data stays in the browser.
- Full-hike estimates and group comparison are available for the verified itineraries below. The nationwide source does not consistently supply verified trailheads, full-route geometry, or elevation gain. Segment pages show those planning fields as unavailable.
- State filtering uses spatial intersection with the Census Bureau’s generalized 2025 boundaries. Trails near borders can appear in adjacent states. To regenerate the boundaries, run `python3 scripts/import-us-states.py`. [Census boundary source](https://www.census.gov/geographies/mapping-files/2025/geo/carto-boundary-file.html)

## Nationwide map

**Map** opens the nationwide overview. Jump to a state, select a verified hike pin, or pan and zoom. At local zoom levels, the app draws the entire USGS Trails layer for the visible area, including land, snow, water, and unnamed trail segments. The map has no search-result limit. Trail detail starts at zoom level 11 to follow the source’s published display scale. [USGS trail layer](https://carto.nationalmap.gov/arcgis/rest/services/transportation/MapServer/37)

Select a trail line to see nearby USGS segment records and open a detail page. The return link restores the map location and zoom. The browser requests a transparent USGS map image after the view settles, and clicking sends a point on the map to USGS to look up its segments. Blue pins open verified planning routes. The verified regional maps remain available in the **Map view** selector.

### Refreshing the route snapshot

```sh
python3 scripts/import-routes.py
```

The importer queries the public NPS GIS layer for the reviewed features in `scripts/routes.json`, checks each park, feature name, segment connection, and itinerary length, and writes `dist/routes.geojson` after all checks pass. Use `--import-date YYYY-MM-DD` to record an explicit import date. Recheck trailheads, segment IDs, mileage conventions, and source notes against official guides before updating the manifest. ArcGIS object IDs are source references and can change. The app IDs do not depend on them. Refresh the catalog manually when NPS updates the routes or source guides. [NPS public trails GIS](https://mapservices.nps.gov/arcgis/rest/services/NationalDatasets/NPS_Public_Trails_Geographic/FeatureServer/0) · [NPS reuse notice](https://www.nps.gov/aboutus/publications.htm)

The map requests visible OpenStreetMap tiles on demand over HTTPS with browser caching and an origin referrer. Map attribution and an issue-report link are visible. [OpenStreetMap tile policy](https://operations.osmfoundation.org/policies/tiles/)

## Forecast and park alerts

- **NWS hourly forecast** · Keyless, free US-government open data, permitted for commercial use. Trailhead coordinates rounded to four decimal places go to `/points`; the adapter follows the returned hourly URL. Forecasts are approximately 2.5 km grid estimates, not trail-wide or upper-elevation measurements. With no chosen time, CURRENT-HOUR FORECAST automatically shows the returned interval containing now, not observed conditions or an invented outing. A past/invalid saved plan remains unchanged and visible, but cannot block that baseline. Use the clearly labelled reset-to-now action to clear a plan explicitly. To override the baseline, enter a complete future date and start time in the park's time zone. The entire estimated outing must fit continuous returned hourly intervals and provider validity, not a fixed seven-day limit; partial, malformed, past, skipped/repeated DST and out-of-horizon selections receive actionable feedback without replacing the saved plan.
- **Honest inputs** · NWS air temperature is **not apparent temperature**. The digest shows air temperature and precipitation chance, with individual missing values marked unknown. Heat/feels-like, gusts and wet/snow factors remain unknown; time, difficulty, comparisons and packing remain terrain/group-only. This is not a weather risk or safety score.
- **Requests and caching** · The static browser sends its real default browser User-Agent, not an app-specific header it cannot reliably override. The [NWS API maintainer's browser clarification](https://github.com/weather-gov/api/discussions/312) (September 2020) accepts that default; the [current FAQ](https://weather-gov.github.io/api/general-faqs) requires a User-Agent and recommends identification/contact information for custom clients. Browser wire evidence is part of the live check. New versioned caches cannot read old Open-Meteo snapshots. Cache-Control and exposed Age bound saved expiry to at most one hour; issues twelve hours old are unknown even with future HTTP expiry. Cache reads, rendering and fetch decisions share freshness eligibility. Expiry and focus revalidate watched routes with in-flight deduplication and a one-minute automatic-attempt bound. Failures do not schedule retry loops; later focus, navigation or explicit submission can retry after outage backoff, honoring exposed Retry-After. The browser also applies its HTTP cache. No API key or paid service is used.
- **Source limitations** · [NWS API documentation](https://www.weather.gov/documentation/services-web-api) · [API FAQ](https://raw.githubusercontent.com/weather-gov/api/master/general-faqs.md) · [NWS disclaimer](https://www.weather.gov/disclaimer). Availability and timely accuracy are not guaranteed; check official conditions before choosing a route or packing.
- **Official alerts** · Each detail page reads the keyless public JSON feed used by that park’s own conditions page and keeps the result in memory for 15 minutes. Alerts are park-wide. If the feed is unavailable, the official conditions link remains visible. A weather forecast cannot establish access, passability, or the presence of ice. If the park-page feed changes, restore alert coverage through the documented NPS Data API with a server-side key. [Zion conditions](https://www.nps.gov/zion/planyourvisit/conditions.htm) · [Rocky Mountain conditions](https://www.nps.gov/romo/planyourvisit/conditions.htm) · [Olympic conditions](https://www.nps.gov/olym/planyourvisit/conditions.htm) · [NPS Data API](https://www.nps.gov/subjects/digital/nps-data-api.htm)

## Browser data migration

The first successful v2 load on the same origin migrates `trail-gauge-v1` into `trail-gauge-v2`. Exact built-in profile fingerprints, identifiable seeded presets and comparison choices, explicitly marked sample reviews, and preset weather are removed. Edited records, ambiguous legacy group arrays, saved preferences, and user reviews are preserved. Stable IDs connect verified routes to old reviews. History keeps reviews of unavailable routes. Any stored conversation content is retained locally as archived data. The sample conversation and thread UI have been removed.

## Verification

Packing presents starter suggestions before the saved checklist. Each requires explicit Add or Dismiss, remembered for that hike and group; adding never marks an item packed or overwrites custom/saved entries. Optional reminders remain in a collapsed disclosure with start/stop controls and in-tab-only limitations. Water, food and refill estimates remain available under trip settings.

The installed-Chrome flow check is `TRAIL_GAUGE_EVIDENCE=<existing evidence directory> node scripts/browser-check.mjs` (macOS, Node 22+). It serves this checkout on an isolated loopback origin and uses a new disposable Chrome profile, never the customer's browser storage. It checks all catalog routes’ live NWS forecasts, the new Great Basin park filter/detail at desktop and mobile sizes, isolated missing/horizon/DST/stale/outage/cache fixtures, all bundled JPEG decoding, gallery keyboard/error credits, and desktop/mobile keyboard disclosure, both packing shortcuts with focus and scrolling, checklist persistence, unanswered/explicit reviews, and horizontal overflow; screenshots and runtime diagnostics go to the evidence directory. `TRAIL_GAUGE_ROOT` can point to an archived baseline's `dist` directory for failure reproduction. Chrome Enter injection includes its carriage-return text so native summary activation is exercised rather than bypassed.
